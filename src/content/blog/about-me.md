## 👋 关于我

你好，我是 **徐恺晨**，一名信息安全专业学生，也是一名仍在持续升级的技术探索者。

我对安全的兴趣，来自一个很朴素的问题：**当系统越来越复杂，我们如何更早发现风险、更可靠地保护用户？** 从 Web 漏洞分析到代码审计，从靶机环境中的攻防演练到联邦学习场景下的安全项目，我喜欢把抽象的安全概念放进真实系统里验证。

现在，我尤其关注 **Security + AI** 的交叉方向。我相信 AI 不会替代安全工程师的判断，但它可以成为一个更高效的协作者：帮助我们理解代码、整理线索、缩短排查路径，把更多精力留给风险建模、验证与决策。

```text
身份标签：Information Security Student / Security Explorer / AI-Native Builder
当前关键词：Web Security · Code Audit · LLM · Engineering Delivery
```

## 🛠️ 技能树 & 关注领域

### Web 安全攻防

我具备常见 Web 安全问题的基础分析与验证能力，持续练习从“漏洞原理”走到“修复建议”的完整链路：

- **输入与查询安全**：SQL 注入、XSS、CSRF；
- **访问控制安全**：越权、身份认证与会话管理问题；
- **文件与服务边界**：文件上传、路径处理与配置风险；
- **安全工程意识**：不只关注“能否打通”，也关注可复现验证、最小化影响与修复闭环。

### AI + Security

我正在把 AI 当作安全研究与工程实践中的协作工具：

- 用大模型辅助梳理漏洞线索、阅读代码与设计测试路径；
- 探索大模型在代码安全检测、风险解释和修复建议中的作用；
- 保持必要的人工验证：**AI 可以提出假设，结论仍要由日志、测试和实际运行结果确认。**

## 🚀 折腾与实践

### AI 辅助靶机攻防：让线索更快收敛

在**授权靶机与学习环境**中，我尝试将 AI 引入信息收集、权限边界分析与提权思路整理。它最有价值的地方，并不是直接给出“答案”，而是帮助我把零散现象组织成待验证的假设：

```text
现象 → 假设 → 验证命令 / 证据 → 调整思路 → 复盘
```

这段经历让我更重视攻防实践中的基本原则：明确授权边界、保留验证证据、理解每个动作背后的系统逻辑，而不是机械地复制命令。

### 基于 AI 的代码审计平台：把模型能力接入安全工作流

我自主实践过一个 **基于 AI 的代码审计平台**，尝试让代码安全检测不止停留在“扫描结果”，而是形成可展示、可追溯的流程：

1. 上传源代码并创建审计会话；
2. 结合规则与大模型分析潜在风险；
3. 输出漏洞等级、影响说明、代码定位与修复建议；
4. 支持围绕已上传代码继续问答，并生成审计报告。

在这个项目里，我不仅关注模型输出，也关注工程落地：服务能否稳定启动、配置是否正确加载、令牌是否能平滑续期、PDF 报告是否能正常生成、漏洞样例是否适合安全展示。对我来说，这正是 AI + 安全项目真正有价值的部分：**让智能能力进入一个可验证、可交付的安全流程。**
