第一次周考结束后，我把自己的作答和试卷逐题核对了一遍。按“多选少选或错选不得分”的规则计算，结果是 **68 / 100**。

看到分数的那一刻，确实有一点“天塌了”的感觉。不是因为它决定了什么，而是因为它把那些平时可以用“我好像会”掩盖的问题，一次性摆在了面前：基础不够牢，知识点记得不全，能说出大概意思，却不一定能把它讲准确、写正确。

冷静下来再想，这次周考其实很有价值。它不是给我贴标签，而是给当前的学习状态做了一次体检。

## 这 68 分是怎么来的

| 部分 | 得分 | 暴露的问题 |
|---|---:|---|
| 单选题 | 20 / 20 | 基础判断题掌握还可以。 |
| 多选题 | 6 / 15 | 对“分类”和“范围”记得不够严谨。 |
| 填空题 | 12 / 15 | `javac`、JVM、字节码执行这条链路混淆。 |
| 问答题 | 20 / 30 | 大方向有了，但接口、抽象类、线程安全的表述不完整。 |
| 编程题 | 10 / 20 | 平均值题能完成；Lambda 与 Stream API 题没有写成可编译、可运行的代码。 |

最扎心的地方不是“不会”，而是很多题我都见过、也能说出一部分；只是到了需要精确回答的时候，记忆和理解没有真正连起来。

## 这次最该补的四块基础

### 1. 先把 Java 的运行链路讲明白

我把 `javac` 和 JVM 的职责弄反了。正确的关系应该是：

```text
.java 源代码 --javac 编译--> .class 字节码 --JVM 加载并执行--> 程序运行
```

`javac` 是编译器，负责把源代码变成字节码；JVM 负责加载、验证、解释执行或通过 JIT 编译执行字节码。以后不能只背关键词，要能把这条链路顺着讲出来。

### 2. 集合与 Stream：不能只记方法名

多选题里暴露的一个问题，是我没有把集合框架的层级真正理顺：

```text
Collection
├── List
├── Set
└── Queue

Map（独立体系，不继承 Collection）
```

另一个误区是把“常用”与“终端操作”混为一谈。`filter` 当然常用，但它是**中间操作**；`collect`、`forEach`、`count` 才是会触发整条流执行的**终端操作**。

我原来写的 Stream 题既不能编译，也没有把题目要求的“筛选、排序、收集为新 List”串起来。正确的最小模板是：

```java
import java.util.List;
import java.util.stream.Collectors;

public static List<String> filterAndSort(List<String> list) {
    return list.stream()
        .filter(s -> s.length() > 5)
        .sorted()
        .collect(Collectors.toList());
}
```

接下来需要练的不是再看一遍答案，而是自己从空白处写出这条链：`stream → filter → sorted → collect`。

### 3. 解释概念时，别停在“差不多对”

接口和抽象类的题目中，我知道接口偏“能做什么”、抽象类偏“是什么”的共同抽象，也知道一个类可以实现多个接口、只能继承一个类。但我漏掉了重要细节：Java 8 之后，接口并不只有抽象方法，还可以有 `default` 方法和 `static` 方法。

线程安全也是类似的问题。它不是“强行让所有线程按顺序执行”，而是多个线程并发访问共享数据时，依然得到正确、可预测的结果。`synchronized`、`Lock`、原子类、并发容器、不可变对象等，分别解决不同场景的问题；`volatile` 主要保证可见性，不能让 `count++` 这类复合操作自动变成原子操作。

这些题提醒我：概念题的标准不是“能感觉到意思”，而是“能说出边界、条件和例外”。

### 4. 代码题要回到编译器

这次平均值方法题完成得还可以：空数组返回 `0`、遍历累加、用 `double` 避免整数除法。真正失分的是第二道题——我把 `Stream.filter(...)` 当成了静态调用，把 `Collections.sort(...)` 当成会返回新列表的方法，还在 `void main` 里尝试返回结果。

这说明我不能只在脑海里“模拟代码”。以后每写完一个小题，都要做最基本的验证：

```text
写出方法 → 编译 → 运行一组样例 → 看输出是否符合题意
```

编译器不会给“差不多”打分，但它会很诚实地告诉我哪里还没有掌握。

光看到问题还不行，必须想办法去落实。不能只盯着文档看，也不能把“看懂了”当成“会做了”：一定要让自己动起来，亲手敲代码、边敲边记，把报错、修改和新的理解都留下来。只有这样，知识点才会从纸面上的结论，慢慢变成真正能用出来的能力。

## 接下来怎么补，而不是只懊恼

我不是一个很聪明的人，但我相信勤能补拙，也相信后程发力需要真实的积累。接下来我会用更具体的方式补基础：

1. **建立错题知识卡**：每道错题不只记录正确选项，还写清“我为什么会选错、正确边界是什么”。
2. **每天手写小模板**：JVM 运行链路、访问权限、集合体系、Stream 流水线、线程安全的常用方式，直到不看资料也能写出来。
3. **把概念变成可运行代码**：例如用一个小程序分别验证 `ArrayList` 与 `LinkedList` 的特点，或写一个 `AtomicInteger` 和 `synchronized` 的对比示例。
4. **每周做一次限时回测**：不靠搜索、不看笔记，用题目检验记忆和理解，再根据结果调整下一周的重点。

68 分不是一个可以被轻轻带过的分数，但它也不是终点。它提醒我：基础不是“以前学过”，而是在被提问、被要求解释、被要求写代码时，依然能稳定拿出来的能力。

把这次失分点一项一项补上。下一次周考，希望我看到的不只是更高的分数，也是一套真正更牢固的 Java 基础。
