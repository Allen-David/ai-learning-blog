最近的学习节奏并不算快，但比以前更踏实一些。

一边维护这个博客，我一边重新认识前端页面是怎么组织出来的；另一边，周考的结果也提醒我，Java 的很多基础不能只停在“有印象”。两个方向看起来不太一样，最后却都指向同一件事：**理解要经过动手、验证和复盘，才能慢慢变成自己的能力。**

> 学习不是把文档看完，而是遇到问题时，能够知道从哪里开始、怎样验证，以及如何把过程留下来。

## 方向 A：从维护博客重新练习前端基础

这段时间前端学习没有从一堆零散的语法题开始，而是直接落在这个 Astro 博客上。把一篇 Markdown 文章放进内容目录，再让它出现在首页、生成独立链接，看起来是一个小流程，但里面其实包含了不少值得反复确认的基础。

### 页面不是“堆出来”的

在调整首页和文章页时，我开始更在意 HTML 结构本身：导航应该放在什么语义元素里，文章标题如何对应页面的主标题，文章列表与标签应该怎样组织。样式当然重要，但一个页面先要有清楚的结构，后面的布局、可访问性和维护才会更顺。

CSS 部分给我的正反馈很直接。改一个间距、调整一条分隔线、让移动端的列表重新排版，浏览器会立刻给出结果；但这种“马上看到变化”也容易让人忽略细节。比如文章列表在手机宽度下曾出现横向溢出，问题不在于颜色或字体，而在于网格列宽和可点击区域没有一起考虑。

这让我记下几个目前仍在坚持的小检查：

- 页面先保证语义清楚，再补视觉层次；
- 交互链接不仅要好看，也要有明确的键盘焦点和足够的点击区域；
- 每次改布局，都至少看一次桌面端和窄屏效果；
- 动效只用来帮助阅读节奏，而不是盖住内容本身。

Astro 也让我对“内容优先”有了更具体的感受。文章是 Markdown，页面负责读取和呈现，构建后输出静态文件。这个过程没有很复杂，却很适合作为理解页面、内容和构建工具之间关系的起点。

## 方向 B：Java 复习要回到原理和编译器

Java 这边的感受正好相反：它没有前端那种立刻看见效果的兴奋，更多时候是在补概念之间的缝隙。

第一次周考之后，我重新回看了集合、Stream、JVM、接口与抽象类，以及线程安全这些内容。很多知识点单独看并不陌生，真正困难的是题目换一种问法后，能不能把边界说清楚、把代码写出来。

### 不只记结论，也要追问“为什么”

例如，`Stream` 的 `filter`、`sorted` 和 `collect` 经常一起出现，但它们承担的角色并不相同：前两个属于中间操作，`collect` 才会触发最终的收集。以前我容易把方法名记住，却没有把整条流水线真正写通；现在更愿意从空白文件开始，把它写到能够编译、运行，再观察结果。

JVM 和 `javac` 的关系也是类似。与其只背“编译器”和“虚拟机”两个词，不如把过程顺着讲一遍：源代码如何变成字节码，JVM 如何加载并执行字节码。能够顺着这条链路说清楚，才说明概念没有停在孤立的标签上。

并发部分目前还在打基础。我不急着把 JUC 的所有工具都记下来，先把线程安全到底在解决什么问题、`synchronized`、原子类和 `volatile` 分别能做什么分清楚。知道一个关键字“能用”并不够，更重要的是知道它不能解决什么。

> 编译器不会因为思路接近就给出正确答案，但它会很诚实地指出理解没有落地的地方。

## 最近形成的一点方法

前端和 Java 的学习体验不同，但我发现可以用同一套简单的流程把它们串起来：

1. **先做一个很小的目标**：一段布局、一个方法、一条 Stream 流水线都可以；
2. **亲手完成并运行**：不只看示例，也不直接复制答案；
3. **记录报错和修改**：报错不是打断，而是下一次复习最具体的入口；
4. **用自己的话复盘**：把“做了什么、为什么这样做、还不确定什么”写下来。

这个流程并不高效得惊人，但它能避免学习停留在文档和视频里。对于现在的我来说，慢一点没有关系，关键是每次都留下一个可验证的结果。

## 总结与下阶段计划

下一阶段，我想继续让两个方向产生一点连接，而不是各学各的：

- 在博客里继续练习响应式布局、内容组织和部署流程；
- 为 Java 的集合、Stream 和并发基础各写几个可运行的小 Demo；
- 尝试做一个很小的前后端练习：前端负责提交和展示，Java 负责提供简单的数据接口；
- 每周安排一次限时回顾，不看笔记完成几道题或一个小功能，再根据结果调整复习重点。

我不期待一下子把所有基础补齐。更现实的目标是：下一次遇到一个概念、一段代码或一个页面问题时，不再只停在“我好像见过”，而是能够打开编辑器，动手把它弄清楚。
